# SenseNova 真实联调报告

测试日期：2026-10-17（Asia/Shanghai）。使用用户提供的单个 API Key，调用 `https://token.sensenova.cn`，经实际编译的 Go 网关转发。凭证仅驻留测试进程内存和子进程环境，不写入项目或报告。测试进程已正常关闭。

主轮和定向复测合并后：**32 项通过、0 项未解决失败、4 项受上游限制**。这里的“受限”表示真实模型未能成功生成，不能解读为所有返回模型均可用。汇总数据见 [final.json](live-test-2026-10-17-final.json)，保留每项来源及原始报告 SHA-256。

## 修复和复测

1. 首轮真实 DeepSeek TPM/RPM 限流导致账号整体冷却，其他模型请求被本地 503 拦截。已将明确的模型引擎限流限定到“账号 + 模型”，并保留上游错误正文和 Retry-After。新增回归测试验证其他模型仍可调用，刷新发现不提前解除冷却。
2. 发现目录含有此账号不能使用的别名。现在明确的套餐不可用 403 会记录 15 分钟的模型排除状态，管理端展示 `unavailable_models`，聚合模型列表过滤对应项目。普通策略／权限 403 保持原有语义。
3. 测试脚本曾对标准响应中的 `error:null` 处理不正确，已修正后继续完成 Responses 等真实调用。
4. 首次图片编辑的测试图为 64×64，上游明确拒绝并说明要求宽高至少 256。改用 256×256 的自建图片后单独复测成功，避免重跑已通过的生成调用。

Go 回归测试 `go test -race ./...` 和静态检查 `go vet ./...` 均通过，实际二进制已重新编译。

## 验证边界

- 只有一个真实额度主体。多账号轮询、切换、并发和故障语义通过模拟上游回归测试；未声称验证了两个独立真实账号之间的切换。
- 官方文档没有公开 API Key 可直接调用的积分余额接口。真实余额仍为未知，可对接用户提供的受支持额度数据源。
- 图片编辑真实验证的是官方 JSON 接口；multipart 的字节透传通过模拟测试验证，不将其描述为 SenseNova 原生协议兼容性已验证。
- 限流会变化，当前成功不保证未来每次均可用，发现目录也不等同于套餐授权。
