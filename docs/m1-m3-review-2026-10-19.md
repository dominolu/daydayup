## P1 修复明细

| # | 问题 | 影响 | 修复 |
|---|---|---|---|
| 1 | 只开启一个桥时，另一协议路径返回**静默空 200**（`maybeBridge` 把"桥未开启"误报为已接管，handler 直接 return） | Claude Code/Codex 打 `/v1/messages`、`/v1/responses` 得到空 200 挂起 | `maybeBridge` 对未开启的桥返回 `(body, false)` 走原透传；补 `TestBridgeSingleEnabledOtherPathPassthrough` |
| 2 | **非流式桥 + 上游 4xx/5xx → HTTP 200 + 错误体两遍**（`bridgeWriter.WriteHeader` 非流式不转发，底层 writer 自动补 200，`finalize` 再写一遍） | 403/400/5xx 错误被伪装成 200，agent 解析异常 | 非流式 `WriteHeader` 在 status≥400 时立即透传；补 `TestBridgeNonStreamUpstreamError` |
| 3 | **JSONC 补丁引擎键位置不限定顶层**：`{"nested":{"model":...},"model":"top"}` 会替换嵌套值而顶层原样保留，静默"状态 OK 但模型没切" | 配置被改错位置且无感知 | `jsonValueRange` 改用 `json.Decoder` 枚举**根对象顶层键**取字节偏移；补 `TestPatchNestedKeyNotShadowed` |

## 已文档化限制（非修复项）

- 桥接丢弃 `reasoning_content`（思考链）与非文本内容块（图片/文档）——README「协议桥的已知限制」已声明。
- 上游 4xx/5xx 错误体按原样透传（OpenAI 错误形态），HTTP 状态与 message 可读。
- `message_start` 输入 token 先报 0，完整 usage 随 `message_delta` 给出。
- 先 usage 后 finish_reason 的异常上游顺序：`message_stop` 可能先于 `stop_reason` delta（部分上游存在，协议偏差可接受，认识先行）。
- 用量聚合对超大归档全量解码（个人单机规模可接受）；备份明文可能含被替换前的旧配置（0600 权限）。
